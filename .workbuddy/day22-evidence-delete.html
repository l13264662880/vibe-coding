Day 22 证据 2｜DELETE 后该条不再返回（软删除，可找回）

接口：DELETE /api/tasks?id=19　·　公网地址：https://yuanjian-d5gdhcntg91022662.service.tcloudbase.com　·　2026-10-10

① DELETE 响应

curl -X DELETE .../api/tasks?id=19
{ "ok": true, "data": { "id": 19, "text": "Day22演示任务", "position": 11, "done": false, "due": null, "estimate": 90 } }

删之前　GET /api/tasks 末尾有 id=19（共 10 条）

{ "id": 14, "text": "给爸爸买生日礼物", "position": 9, ... },
{ "id": 19, "text": "Day22演示任务", "position": 11, "done": false, "due": null, "estimate": 90 } }
↓ DELETE /api/tasks?id=19

删之后　GET /api/tasks 返回末尾（该条已消失，共 9 条）

{ "id": 7, "text": "投递三家公司的简历", "position": 6, ... },
{ "id": 5, "text": "买好明天的早饭", "position": 7, "done": true, ... },
{ "id": 14, "text": "给爸爸买生日礼物", "position": 9, ... } }
// id=19「Day22演示任务」已不在 GET 返回里 ✓　重复 DELETE 再试 → 404 任务不存在 ✓

③ 软删除证据：数据没真删，数据库里行还在（删错了可找回）

GET 网关 /tasks?id=eq.19　（直接查库，不走接口过滤）
[{ "id": 19, "text": "Day22演示任务", "position": 11, "estimate": 90,
   "deleted_at": "2026-10-10T22:50:37.517+08:00" }]

-- task_events 事件链（本次 id=19 全程留痕）--
{ "event_type": "created", "task_id": 19 }
{ "event_type": "edited",  "task_id": 19 }
{ "event_type": "done",    "task_id": 19 }
{ "event_type": "deleted", "task_id": 19, "to_position": 11 }

原理：DELETE 只把 deleted_at 置为当前时间（Day 16 schema 就有这列），读接口全带 deleted_at IS NULL 过滤，行自然「消失」；把 deleted_at 清空即可找回。
