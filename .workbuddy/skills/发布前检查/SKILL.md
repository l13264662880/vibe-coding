# 发布前检查（pre-release check）

把「上线前人工过一遍」的检查项固化成一条命令，防止带着坏状态发布。

## 怎么跑

```bash
# 全量检查（8 项）
python tools/pre_release_check.py

# 最小版（只查公网 + 密钥，2 项）
python tools/pre_release_check.py --quick
```

退出码：`0` = 全部通过；`1` = 有 FAIL（FAIL 明细打印在汇总区）。

## 检查项（全量）

| # | 检查 | 不过的常见原因 |
|---|------|---------------|
| 1 | 公网首页 200 | 静态托管未部署 / CDN 缓存旧版 |
| 2 | `/api/health` ok:true | 云函数未部署 / 环境休眠 |
| 3 | `GET /api/tasks` ok:true | 令牌失效 / 网关异常 |
| 4 | `.env` 未被 git 跟踪 | 误 `git add .env` |
| 5 | 源码无硬编码密钥真值 | 调试代码残留（PAT/令牌） |
| 6 | 云函数 `node --check` 全过 | 语法错误 |
| 7 | 桌宠冒烟测试 | 分层渲染/换装/动画回归失败 |
| 8 | 工作区干净（提醒） | 有未提交改动 |

## 判定标准

- 全 PASS → 可以发布。
- 任何 FAIL → **不发布**，先修再重跑；把 FAIL 明细原样贴给用户。

## 边界（只检查，不改代码）

- 第 8 项是提醒，不阻断（有意带改动发布时可忽略）。
- 检查目标（URL）集中在脚本顶部 `SITE_URL / API_BASE`，换环境只改那两行。
- 想加检查项：在脚本里加一个 `check_xxx()` 并登记进 `FULL_CHECKS`，不要写死在 `main()` 里。
